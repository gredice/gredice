# Autumn publication preparation (#5000)

This tool prepares the missing publication workflow. It does not make the autumn release ready. Development used synthetic fixtures, disposable PGlite and disposable local PostgreSQL validation. No live publication, catalogue/config edit, live DB read, deployed URL read, or sales enablement was performed. Existing family manifests retain their original unpublished state and null catalogue IDs.

The default is offline: `pnpm plan:autumn-publication /absolute/new-output-directory`. It checks the same reviewed source/model/preview/picker inputs as the consolidated preflight and reports the 24 unresolved A/B item identities when no CMS snapshot is supplied. No storage client, environment-file loader, network request, or database is invoked. Output directories must be new; files are written with exclusive creation. Input JSON is limited to 10 MB before parsing, arrays and strings are bounded, and repository source readers reject escaping paths/symlinks. These commands use the checked-out source and work in source archives without Git history, except the explicit apply mode requires a clean committed Git checkout.

The source scope is exactly the twelve A/B families (24 static runtime names, 16 new GLBs). Optional C/Later items are excluded. Pumpkin/aster colours are distinct runtime identities mapped to their existing shared GLBs, not fabricated alias-model URLs or numeric variants. The publication plan writes only the 24 new items. StoneMedium and EnamelGardenLamp are read-only prerequisites reconciled separately from the actual published-directory export when preparing the three product candidates; they are never republished by this batch.

## Offline plan and candidates

`pnpm plan:autumn-publication /absolute/new-plan-directory --cms /absolute/cms-export.json` emits `publication-plan.json` and a report containing its full SHA256 digest, resolved IDs, frozen actual individual prices, expected state/revision/content digests and publish/noop actions. The CMS export has schema version 1, the active block definitions and the selected entities' raw attributes and latest audit revisions. Its strict schema is `packages/storage/src/helpers/autumnPublicationPlan.ts`; the explicit read-only export command below produces it. Fixture IDs/prices are restricted to tests and are not a seed/import.

Every selected name must resolve uniquely to a positive actual ID. Required content must be complete, exact reviewed text/attributes/functions/cover must already exist, prices must be positive integer ordinary prices, and hierarchy inheritance is rejected. No attributes, prices, dates or IDs are created or repaired by the publisher. The complete active definition semantics and all selected raw attribute identities/values/update timestamps are frozen. Unrelated legacy entities with retired definitions are outside the batch and do not need cleanup. Duplicate selected names still block the entire batch.

`pnpm plan:autumn-publication /absolute/new-candidates-directory --mode candidates --catalogue /absolute/published-blocks.json --window /absolute/snapshot-window.json` prepares the exact three reviewed four-piece recipes. The input must be an actual read-only published-directory export, not projected draft rows. It must contain all 24 reviewed family items plus both existing dependencies with positive unique identities/prices, exact public metadata and cover URLs. A structural offline check cannot authenticate where an operator obtained that export; its input hash is recorded and actual published-directory/cache readback remains a separate gate.

The window file must explicitly contain both `availableFrom` and `availableUntil`, each a valid instant or `null`. There are no default commercial dates. Promotion changes immutable publication state, so the candidates receive newly computed full content/evidence fingerprints; bought versions are never edited. Each line freezes its current ordinary paid value and equal recycling value, with no discount or scenery charge. Every emitted offer has `sale.enabled=false` and no sale window. `sales-disabled-candidates.json` is a review artifact: the command never installs configuration, changes flags, registers purchases, debits a wallet or enables sales. Existing configuration loading and purchase-time immutable-version registration remain authoritative.

## Explicit operational modes (not invoked for this PR)

The read-only CMS export mode is `pnpm plan:autumn-publication /absolute/new-export-directory --mode export-cms --scope autumn-ab-pilot`. It imports storage only after explicit mode/scope selection and source validation, reads a consistent repeatable-read snapshot, and writes `cms-export.json`. It does not load `.env` files. An authorized operator must supply the normal storage environment separately; possessing a plan does not authorize use of any environment.

Actual apply requires every explicit argument: `pnpm plan:autumn-publication /absolute/new-apply-directory --mode apply --scope autumn-ab-pilot --plan /absolute/publication-plan.json --digest <full-reviewed-SHA256> --actor-id <actual-operator-id> --actor-name <actual-operator-name>`. CLI input is not review authority: it reconstructs the entire plan from current validated reviewed source and requires exact equality before any deployed read or DB import. Removing asset checks, relaxing reviewed fields, changing source identity, or supplying a self-consistent forged digest cannot pass this reconstruction. The internal storage primitive is intended only for this authoritative operator entry point; no new HTTP/auth surface is exposed.

Apply requires a clean committed checkout and reads the exact reviewed public asset bytes at the canonical Garden and WWW origins. It checks the full source-selected public asset inventory (currently 283 paths: 22 GLBs, 258 WebPs and three other images), including legacy/scenery assets, rotated top-down files and arrangement previews. Named legacy model versions such as Tree's existing URL remain exact. Redirects, unknown hosts, duplicate URLs, oversized responses, missing bytes and hash/size mismatches fail before database access. Read concurrency is four, each request is bounded to ten seconds, the whole verification to 120 seconds, and private freshness starts at the first read. Submitted `deployed=true` flags and self-attested observations are never accepted. The resulting observations are retained privately and copied for reporting; mutable caller fields cannot change audit evidence or extend freshness.

No network runs while locks are held. The state-only storage adapter obtains SHARE ROW EXCLUSIVE locks on entities, attribute values, attribute definitions and entity revisions in one transaction, with a two-second lock timeout, 15-second statement timeout and checked 30-second transaction budget. This intentionally fences ordinary CMS inserts/edits too: generic writers do not consistently acquire a parent-entity lock. During this rare explicit batch, unrelated CMS writes may briefly wait; reads continue. It rereads current content, globally resolves duplicate selected names and verifies every precondition before the first write. Missing/stale identities, content, prices, definitions or revisions abort the entire batch. State changes, actual publication timestamps and audit rows commit together; no migration is needed.

The audit action `entity.autumn_published` stores the explicit actor, previous draft state, published next state, original entity digest and plan digest. Reapplying the exact plan recognizes only its own prior publication or an originally identical published item. It preserves `publishedAt`, updated timestamp and revision count on noops; unrelated later revisions or even reverted attribute updates require a fresh plan. Concurrent identical applications publish once and replay once. The command never implicitly adopts an unrelated edit.

Cache/directory/dashboard invalidation and direct search refresh occur after commit, including on exact noops. A refresh failure returns `database:committed` and `refreshStatus:pending`; retry the same plan to repair it without a new revision. DB/network failures may leave a response uncertain, so only the same reviewed plan should be retried. Native driver errors/clients/credentials are not printed. A postcommit artifact write failure explicitly retains the committed outcome rather than claiming rollback. Database commit, cache refresh, WWW revalidation, CDN public metadata/readback and distributed visibility are separate stages: cache invalidation cannot fence an in-flight refill and does not perform WWW's separate revalidation action.

Even successful apply reports `releaseReady:false`: these reads prove only the specific asset URLs, not deployed runtime registrations/UI, final CI, physical touch/audio/thermal acceptance or live commerce. Public directory/price/cache readback is required before product-candidate regeneration. Product config review/installation remains explicit and sales-disabled; no offer is installed here. Existing immutable ownership and lifecycle continue after later sale withdrawal. #4999/#5000 release acceptance and the epic remain open until the separate recorded gates are met.

## Focused validation

`pnpm --filter api exec node --import tsx --conditions=react-server --test ./lib/garden/autumnPublicationPlan.node.spec.ts` runs nine offline/authority/version/byte/CLI cases and the isolated eight-case transaction suite through the existing API CI test discovery, preserving workflow and visual evidence pins. The harness defaults to disposable PGlite; it can use the existing explicit local-only `GREDICE_PACK_TEST_ADMIN_URL` PostgreSQL harness. It rejects non-local host/username/database combinations, creates its own database and drops it afterward. PGlite proves rollback/replay invariants and serial submissions; only PostgreSQL proves independent transactions and the active CMS-writer lock timeout.
