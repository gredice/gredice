# Optional pumpkin-lighting trail

Issue #4998 adds the public `/staza-bundeva` sample, discoverable through “Posjeti stazu bundeva” on the public Kestenijada page. Participation is optional and available without login, purchases or a daily visit. It grants no rewards, charges no currency and changes no customer garden. The ordinary autumn and pumpkin decorations remain usable outside the trail.

The authored scene is a 5×5 grass board translated by (−2, −2). Five separately supported Smile/Wink lanterns carry matching numbered mesh badges and native DOM buttons below the canvas. A U-shaped stone path, friendly ghost, supported cobweb, hay bale and dead tree frame the stops. This is an existing-model arrangement, not an asset export. BaleHey uses private render-only metadata because it is absent from the local sandbox catalogue; all display rows have negative identities and zero prices, and never enter a commerce or ownership cache.

Start enables the five buttons and real pumpkin mesh clicks/taps, then moves keyboard focus to the first stop. Both input paths use the same exact-ID guarded action. Pre-start and non-stop clicks do nothing; activating a stop never changes the fixed camera. Stops can be lit in any order; repeated activation is harmless. A live status reports the lit count and completion. Reset creates a fresh scene and clears every light. Reload, navigation away (including a pagehide/back-forward-cache transition) and a new visit also start fresh; nothing is persisted or reported to the activity/reward service. Sumrak is the default, with optional day and night views that retain the current session's lights.

The `PumpkinLightOverrideContext` maps exact display block IDs to explicit on/off state and an optional scoped activation callback. Only this viewer provides it. Missing keys outside this context retain the ordinary shared day/night policy. Explicit off lamps are excluded from physical-light candidates. Explicit on lamps use steady amber emissive faces and the existing frustum/quality budget; low quality permits four physical lights while all five faces remain emissive. There is no blinking, motion dependency or audio. Reduced motion and mute require no separate mode. Registry cleanup releases light registrations, marker textures are disposed, the isolated viewer cache is cleared on unmount, and no animation lease is added by the trail itself.

The camera uses the existing orthographic fitting helper and the reviewed arrangement bounds (7.0711×5.5415, target Y0.893), with padding and the measured canvas size. Desktop max zoom is 82; mobile canvas height is 360px. Controls stay below the canvas. Model/context failure removes participation controls and offers a page refresh, which also retries cached model-load failures with a fresh scene.

The root provider bypasses auth only for exact Kestenijada and pumpkin-trail paths (including their trailing slashes). Other paths keep normal authentication. `PublicGardenViewer` disables authenticated garden queries and seeds its render-only blocks, empty sorts and empty operations into its own cache; no public-share ID or account/cache fallback is used. The trail does not publish, upload or modify sharing status.

Validation uses `playwright.pumpkin-trail.config.ts` (one WebGL worker, port 5491) for real geometry, nonblank pixels, real mesh mouse/touch picks, unchanged camera, keyboard, any-order/repeat/reset, mobile touch, reduced motion, phase changes and outside-context default lighting. `playwright.pumpkin-trail-route.config.ts` runs against a local production Next build on the same exclusive port to verify direct public access, reload/navigation privacy, preservation of normal auth, same-origin models and unavailable-model refresh recovery. Pure tests cover stable scene identities/supports, exact public-path allowlisting, idempotent progression and ordinary/manual light policy. Final visual review and existing capture-source evidence remain separate integration checks.
